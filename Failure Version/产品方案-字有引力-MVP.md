# 《字有引力》MVP 产品方案

## 1. 产品定位与首版目标

**孩子学会的每一个字，都能成为改变世界的工具。**

面向 5—8 岁、认识少量汉字的孩子，制作手机竖屏优先的黏土风识字冒险游戏。孩子通过描摹、拼字和使用汉字修复小岛，帮助小狐狸回家。

首版按一天黑客松演示规模开发：**一座岛、三个连续任务、三种过河解法、一次迁移挑战**。正常体验约 5 分钟，现场可在 3 分钟内展示核心过程。

采用 React＋TypeScript＋Vite、SVG＋CSS 动画、LocalStorage；Express 接入真实 AI。角色支持朗读，孩子通过文字表达自由想法。首版不做语音输入、登录、多章节、成语和古诗词。

## 2. 核心玩法与学习闭环

首页直接进入小岛：树木枯萎、河床干涸，小狐狸在另一岸等待帮助。第一次点击“帮助小狐狸”后开始引导和声音播放。

| 环节 | 孩子的操作 | 场景反馈与学习目标 |
|---|---|---|
| 任务一：让树林回来 | 在描摹面板依次写出“木”；再把两个“木”放进组合槽 | 一棵树长出来；两个“木”吸附成“林”，树林展开，认识字形与构形 |
| 任务二：让河水回来 | 将“雨”放进天空 | “雨”短暂停留，随后化成雨滴，河水恢复，建立汉字与字义的联系 |
| 任务三：帮助狐狸过河 | 使用“桥”，或向狐狸输入其他办法 | 对应出现桥、船或鸟；完成后狐狸到达家门 |
| 迁移挑战：给花园浇水 | 在新花园中从“木、雨、鸟”里选字并使用 | 再次使用“雨”让花朵恢复，验证换情境后是否仍能理解字义 |
| 完成反馈 | 查看自己的成果，选择重玩 | 展示修复后的小岛、使用过的汉字和过河办法 |

**首版字库固定为“木、林、雨、桥、船、鸟”。** 每个字有经过人工核对的字形、拼音、短释义和示例；AI 不负责生成这些知识。

具体交互约定：

- “木”使用田字格、起笔点和逐笔描摹提示。按笔顺检查方向及是否大致沿参考路径完成，允许重试；这是引导描摹，不宣称具备自由手写识别或书法评分能力。
- 描摹成功后提供两个可复用的“木”字块；组合槽展示“两棵树”的视觉提示，完成后获得“林”。
- 字块支持拖拽，也支持“点字块→点目标”的替代操作。放错位置时字块返回，并给出短提示。
- 桥、船、鸟都能完成同一任务；鸟采用童话中的大鸟角色，表现为搭载狐狸过河。
- AI 给出建议后先展示待确认字块；孩子点击“试试这个办法”，观察字义，再亲手使用。AI 回复本身不直接通关。
- 尚未支持的想法先得到简短回应，再引导尝试已有工具；不假装生成了新的游戏能力。
- 不设置倒计时、排行榜或失败扣分。多次尝试后增加图示提示。

## 3. 黏土风 UI 与动效

**视觉主张：一座可以用汉字捏活的掌心小岛。** 场景和角色采用圆润轮廓、哑光表面、柔和高光与接触阴影；汉字保持清楚、标准的字形。

手机主界面由上到下排列：

1. **轻量顶栏**：产品名、声音开关、小岛进度图标。
2. **主场景**：约占首屏一半，展示小岛、狐狸和当前可操作目标。
3. **狐狸提示区**：头像、一句短提示、重播按钮和“我有个办法”入口。
4. **底部字块工具栏**：当前任务所需的少量字块，避免一次展示全部字库。

描摹使用底部展开面板；自由表达使用输入面板，打开时收起字库并避让软键盘。完成页继续以小岛为主视觉，不另建学习数据仪表盘。

设计令牌与操作标准：

| 项目 | 约定 |
|---|---|
| 配色 | 奶油底 `#FFF7E8`、狐狸橙 `#D96A37`、深棕文字 `#3E3028`；草绿和水蓝用于场景 |
| 字体 | 界面使用系统中文无衬线字体；教学汉字使用清晰的楷体资源，实施时确认授权 |
| 字号 | 正文 18px、任务提示 22px、标题 28px、字块汉字 40px |
| 间距 | 4、8、12、16、24、32px |
| 圆角 | 控件 16px、面板 24px，字块带浅立体边缘 |
| 触控 | 主要按钮和字块至少 56×56px；选中状态同时使用描边与形状反馈 |

重点制作三组解释字义的动效：

- **描摹**：笔画随手指出现，完成后字形轻轻鼓起，第一棵树从落点生长。
- **组合**：两个“木”靠近组合槽时吸附，过渡为“林”，场景中的树木依次展开。
- **使用**：“雨”化为雨滴，“桥”展开成桥面；船和鸟沿固定路线带狐狸过河。

按压反馈约 120ms，吸附和面板过渡约 250ms，主要场景变化约 1—2 秒。只保留轻微的狐狸呼吸、水面变化等环境动效。减少动态效果时改用淡入和直接状态切换。

加载、失败和辅助状态统一处理：AI 等待时显示“让我想一想”，输入保留；失败后可以重试或直接选字。朗读不可用时保留文字、图示和重播入口的明确状态。所有主要操作支持键盘焦点，拖拽有点选替代，文字对比度按 WCAG AA 验收。

## 4. 技术实现与 AI 分工

**前端规则决定世界能发生什么，AI 理解孩子想做什么。**

- 前端使用明确的任务状态机，管理植树、组合、降雨、过河、迁移和完成阶段。教学数据、目标位置及动画由本地配置提供。
- SVG 分层绘制天空、地面、河流、植物、角色及过河工具；CSS 控制高光、阴影和动画。使用 Pointer Events 统一鼠标和触摸操作。
- LocalStorage 保存版本号、当前任务、已获得字块、已使用汉字、过河办法和声音偏好。只在操作完成后保存稳定状态，刷新后不重复执行通关动画。
- 不保存自由输入全文和音频。存储不可用时继续内存游戏并提示无法保存；提供“重新开始”入口。
- 固定教学提示使用随应用提供的普通话音频；动态 AI 回复尝试浏览器中文语音合成，失败时显示文字。声音从首次用户点击后启用。

Express 提供一个接口：`POST /api/intent`。

| 接口内容 | 最小约定 |
|---|---|
| 请求 | 孩子的输入、当前任务、世界状态、已接触汉字、当前允许的行动 |
| 响应 | 简短引导语、建议行动、对应汉字、是否需要澄清 |
| 行动范围 | `build_bridge`、`use_boat`、`call_bird`、`clarify`、`unsupported` |

服务端通过可配置的 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY` 调用兼容 Chat Completions 的模型；密钥只保存在服务端环境变量。

AI 引导使用一至两句儿童可理解的中文，围绕当前任务回应。服务端校验结构和行动枚举，前端再次检查任务是否允许执行；AI 不能修改字义、解锁任意对象或返回可执行代码。根据描摹尝试次数和已接触汉字调整提示详细程度，不将其描述为完整的能力测评。

请求超过 8 秒、服务不可用或返回结构无效时，保留当前进度，提供固定的桥、船、鸟选字玩法。基础玩法和音频随应用提供，可在 AI 断线时继续游玩；开发者状态入口明确显示真实 AI 是否连接成功。

## 5. 实施顺序与验收

实施顺序固定为：

1. 搭建竖屏场景和规则闭环，先实现点选字块及三种过河动画。
2. 加入“木”的描摹、“林”的组合、拖拽和迁移挑战。
3. 接入 Express、真实意图理解、确认步骤及失败回退。
4. 完善黏土材质、音频、进度恢复和现场演示入口。

验收覆盖：

- 六个汉字的字形、读音、释义，以及“木”的笔顺经过人工核对。
- 三条过河路线分别可完成；重复点击、错误落点和旧 AI 回复不会跳过任务或重复通关。
- 输入“坐船过去”“让狐狸飞过去”等表达，真实接口分别建议“船”和“鸟”，仍由孩子亲手完成操作。
- 模糊或不支持的表达能得到澄清；AI 断线和无效响应时基础玩法完整可用。
- 刷新后恢复稳定进度；重新开始能清空本次记录。
- 在 360—430px 宽的手机竖屏中验证描摹、点选、拖拽及软键盘避让，同时保留电脑演示适配。
- 为状态转换和 AI 响应校验编写关键测试；通过真实浏览器人工验收动画、触摸和音频。
- 有条件时，在家长同意下进行一次五分钟儿童试用，观察能否找到第一步、是否主动再试、是否能在花园中再次选出“雨”；没有试用时不声称已有学习效果证据。

现场演示依次展示：**写“木”→拼“林”→用“雨”→输入意外解法→亲手使用“船”或“鸟”→花园迁移挑战**。验收重点是观众能看见汉字改变世界，并能分辨 AI 在自由表达理解中承担的实际作用。
